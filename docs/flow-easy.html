Hospital Carepath ทำงานยังไง?

เปรียบเทียบกับการไปโรงพยาบาลจริงๆ ให้เห็นภาพ

🗺️ ภาพรวมทั้งหมด (อ่านก่อน)

ระบบทำงานเป็น 4 ขั้นตอนต่อผู้ป่วย 1 คน ตั้งแต่เดินเข้าโรงพยาบาลจนกลับบ้าน:

  1. เดินเข้ามา → POST /patients (ลงทะเบียน)
  2. หมอตรวจเสร็จ → PATCH /patients/{id}/pathway (เลือกแผนการรักษา)
  3. พยาบาล/หมอต้องดูสถานะ → GET /patients/{id}/pathway (ดูขั้นตอนปัจจุบัน)
  4. ทำเสร็จแต่ละขั้น → PATCH /visits/{id}/steps/{n} (ติ๊กว่าเสร็จ)
ขั้นที่ 1 · ลงทะเบียน

🚪 เดินเข้าโรงพยาบาล กรอกประวัติที่เคาน์เตอร์

เปรียบเหมือน: คุณเดินเข้าโรงพยาบาล ไปยื่นบัตรประชาชนที่เคาน์เตอร์ พนักงานถามชื่อ อาการ เบอร์โทร แล้วออกบัตรคิวให้ (เช่น A023)

ระบบทำอะไร:

  • รับชื่อ อาการ เบอร์โทรจากผู้ป่วย
  • สร้างรหัสผู้ป่วยอัตโนมัติ (เช่น P0002) — เหมือนบัตรคิว
  • บันทึกสถานะเริ่มต้น = "admitted" (เพิ่งมาถึง)
  • ยังไม่รู้ว่าต้องรักษาอะไร — รอหมอตรวจ
ผลลัพธ์: ผู้ป่วย P0002 อยู่ในระบบแล้ว แต่ยังไม่มีแผนการรักษา
POST/patients
ขั้นที่ 2 · เลือกแผนการรักษา

🩺 หมอตรวจเสร็จ เลือกแผนว่าต้องทำอะไรบ้าง

เปรียบเหมือน: หมอตรวจเสร็จแล้วบอกว่า "คุณเป็นเบาหวาน ต้องติดตามอาการ" แล้วหมอเปิด "แผนติดตามเบาหวาน" ซึ่งระบุไว้แล้วว่า ต้องเจาะเลือด → เช็คเท้า → พบหมอ → รับยา → กลับบ้าน

ระบบทำอะไร:

  • Frontend ส่ง template_code: "diabetic_followup" มาบอก
  • Backend เปิดแผนนี้ในฐานข้อมูล → เห็นว่ามี 7 ขั้นตอน
  • ระบบสร้าง "Visit" ใหม่ (เหมือนเปิดครั้งใหม่ของการรักษา)
  • ระบบสร้าง "VisitSteps" ทั้ง 7 ขั้นตอนอัตโนมัติ สถานะเริ่มต้น "pending" (รอทำ)
  • บันทึกหมายเหตุพิเศษ เช่น ["fast_required", "wheelchair"] = งดน้ำงดอาหาร + ใช้รถเข็น
ผลลัพธ์: ตอนนี้ผู้ป่วยมี "ตารางงาน" ชัดเจน — ทุกคนรู้ว่าต้องทำอะไร เรียงลำดับยังไง
PATCH/patients/{id}/pathway
ขั้นที่ 3 · ดูสถานะ

📺 เปิดจอดูว่าตอนนี้อยู่ขั้นไหน

เปรียบเหมือน: หน้าห้องตรวจมีจอทีวีใหญ่ บอกว่า "P0002 สมชาย — กำลังรอเจาะเลือด" พยาบาลเดินผ่านก็รู้ได้ว่าคนไหนต้องไปทำอะไรต่อ

ระบบทำอะไร:

  • Frontend ถาม backend: "ตอนนี้ P0002 อยู่ขั้นไหน?"
  • Backend ดึงข้อมูลจาก 3 ตารางมารวมกัน:
    • patients → ชื่อ อาการ
    • pathway_templates → แผนการรักษา + ขั้นตอนทั้งหมด
    • visits + visit_steps → สถานะปัจจุบัน
  • ส่งกลับเป็น JSON ให้ frontend เอาไปวาดเป็นตาราง/การ์ด
ผลลัพธ์: Frontend ได้ข้อมูลครบ เอาไปแสดงในจอหรือหน้าจอมือถือของหมอ/พยาบาล
GET/patients/{id}/pathway

🟢 เขียว = เสร็จแล้ว · 🟡 เหลือง = กำลังทำ · ⚪ เทา = รอทำ

ขั้นที่ 4 · อัปเดตความคืบหน้า

✅ พยาบาล/หมอติ๊กว่าทำเสร็จขั้นตอนนั้นแล้ว

เปรียบเหมือน: พยาบาลเช็คชีพจรเสร็จ เธอหยิบ Tablet มากด "ขั้นที่ 2 เสร็จแล้ว ใช้เวลา 5 นาที" ระบบก็บันทึกเวลาเริ่ม-เวลาจบ + ชื่อคนทำ + หมายเหตุให้อัตโนมัติ

ระบบทำอะไร:

  • รับสถานะใหม่: pending → in_progress → completed
  • ถ้าเริ่มทำ → ระบบบันทึกเวลาเริ่มให้อัตโนมัติ (ไม่ต้องกรอกเอง)
  • ถ้าเสร็จ → ระบบบันทึกเวลาจบให้อัตโนมัติ
  • เก็บชื่อคนทำ (performed_by) และหมายเหตุ (notes) เพิ่มเติมได้
ผลลัพธ์: ผู้ป่วย P0002 ขั้นที่ 2 เปลี่ยนเป็น "completed" ทันที คนอื่นเปิดดูก็เห็นว่าเสร็จแล้ว
PATCH/visits/{id}/steps/{stepOrder}

📋 สรุปสั้น — จำแค่นี้ก็พอ

เหตุการณ์ในชีวิตจริงAPI ที่ใช้เหมือนอะไร
🟢 ผู้ป่วยเดินเข้ามา POST /patients กรอกประวัติที่เคาน์เตอร์ รับบัตรคิว
🟡 หมอเลือกแผนการรักษา PATCH /patients/{id}/pathway เปิด "คอร์สการรักษา" พร้อมรายการขั้นตอน
🔵 พยาบาลเปิดดูสถานะ GET /patients/{id}/pathway ดูจอทีวีหน้าห้องตรวจ
🟠 ทำเสร็จขั้นตอนหนึ่ง PATCH /visits/{id}/steps/{n} ติ๊ก checkbox บน Tablet ว่าเสร็จแล้ว

🧠 จุดสังเกต

  • POST = สร้างใหม่ · GET = ดูอย่างเดียว · PATCH = แก้บางส่วน
  • หลังจากเลือกแผน ทุกอย่างทำงานอัตโนมัติ — ไม่ต้องสร้าง Visit/Steps เอง
  • ขั้นตอนทั้งหมดเก็บ "ใครทำ · ทำเมื่อไหร่ · หมายเหตุอะไร" — เพื่อตรวจสอบย้อนหลังได้
  • ผู้ป่วย 1 คนสามารถมีหลาย Visit ได้ (เช่น กลับมาติดตามครั้งใหม่)
