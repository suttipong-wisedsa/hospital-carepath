Hospital Carepath · Backend Flow

Flow: สร้างผู้ป่วย → เลือก Care Pathway → ติดตามขั้นตอน

เอกสารอธิบายการทำงานของระบบ Hospital Carepath API ตั้งแต่ลงทะเบียนผู้ป่วย จนถึงการติดตามสถานะแต่ละขั้นตอนของ Care Pathway ผ่าน HTTP API

🟢 Go + GORM 🐘 PostgreSQL 🌐 RESTful HTTP 📦 JSON

🏛️ภาพรวมสถาปัตยกรรม

ระบบแบ่งเป็น 4 ชั้น — Client → HTTP Handler → Store (GORM) → Database

Frontend / curl / Postman
▼
HTTP Layer (Handlers)

🩺Flow ทีละขั้นตอน

4 ขั้นตอนหลักในการนำผู้ป่วยเข้าสู่ Care Pathway

1
ลงทะเบียนผู้ป่วยใหม่
POST /patients

Request

POST /patients
Content-Type: application/json

{
  "name":    "สมชาย ทดสอบ",
  "gender":  "M",
  "age":     45,
  "phone":   "081-111-2222",
  "symptom": "ปวดหัว มีไข้"
}

สิ่งที่ระบบทำ

// ใน patient.Handler.create
1. validate name (ต้องไม่ว่าง)
2. gen code = MAX(code) + 1
   → "P0002"
3. INSERT patients
   status='admitted'
   pathway_template_id=NULL
   special_conditions='[]'

Response (201)

{
  "id": "P0002",
  "name": "สมชาย ทดสอบ",
  "status": "admitted",
  "special_conditions": []
}
2
เลือก Care Pathway Template
PATCH /patients/{id}/pathway

Request

PATCH /patients/P0002/pathway
Content-Type: application/json

{
  "template_code": "diabetic_followup",
  "special_conditions": [
    "fast_required",
    "wheelchair"
  ]
}

สิ่งที่ระบบทำ

// ใน patient.Handler.assignPathway
1. pathwayStore.GetByCode("diabetic_followup")
   → template_id = 1
2. UPDATE patients
     SET pathway_template_id=1,
         special_conditions='[...]'

// trigger auto-create Visit+Steps
3. visitStore.CreateFromPathway("P0002", 1)
   a) ดึง stages: ["registered",
      "vitals_check","waiting",
      "in_consultation","lab",
      "treating","discharged"]
   b) INSERT visits (status='active')
   c) INSERT visit_steps × 7
      (status='pending')

Response (200)

{
  "id": "P0002",
  "template_code": "diabetic_followup",
  "special_conditions": ["fast_required","wheelchair"],
  "visit_id": 7,
  "steps_created": 7
}
3
ดู Pathway ปัจจุบันของผู้ป่วย
GET /patients/{id}/pathway

Request

GET /patients/P0002/pathway

ใช้ทำอะไร

Frontend ใช้แสดง template + special conditions ของผู้ป่วย พร้อม stages ทั้งหมดเพื่อให้ผู้ใช้เห็นภาพรวม

Response (200)

{
  "patient_id": "P0002",
  "patient_name": "สมชาย ทดสอบ",
  "pathway_template": {
    "code": "diabetic_followup",
    "name": "ผู้ป่วยเบาหวานรายเก่า",
    "stages": [
      "registered", "vitals_check",
      "waiting",     "in_consultation",
      "lab",         "treating",
      "discharged"
    ]
  },
  "special_conditions": [
    "fast_required", "wheelchair"
  ]
}
4
ติดตามสถานะแต่ละขั้นตอน
PATCH /visits/{id}/steps/{stepOrder}

Request — เริ่มขั้นตอน

PATCH /visits/7/steps/1
{
  "status": "in_progress",
  "performed_by": "พยาบาลแนน",
  "notes": "ลงทะเบียนเรียบร้อย"
}

Request — จบขั้นตอน

PATCH /visits/7/steps/1
{
  "status": "completed"
}

Lifecycle

pending → in_progress → completed | skipped

สิ่งที่ระบบทำ

// ใน visit.Store.UpdateStepStatus
1. validate status (enum)
2. UPDATE visit_steps
     SET status='in_progress',
         started_at=NOW()   // auto
3. เมื่อ status='completed':
     SET completed_at=NOW() // auto
4. UPDATE performed_by, notes (optional)

Response (200)

{
  "id": 38,
  "visit_id": 7,
  "step_order": 1,
  "stage": "registered",
  "status": "completed",
  "started_at":   "2026-09-19T13:57:01Z",
  "completed_at": "2026-09-19T13:57:02Z",
  "performed_by": "พยาบาลแนน"
}

🔌API Endpoints

RESTful HTTP — JSON request/response

MethodPathคำอธิบาย
GET/หน้าแรก + รายการ endpoint
GET/healthตรวจสถานะ service
POST/patientsลงทะเบียนผู้ป่วยใหม่
GET/patientsดูรายการผู้ป่วยทั้งหมด
GET/patients/{id}ดูข้อมูลผู้ป่วยตาม code
PATCH/patients/{id}/statusอัปเดตสถานะผู้ป่วย
PATCH/patients/{id}/pathwayเลือก Care Pathway Template (auto-create Visit+Steps)
GET/patients/{id}/pathwayดู pathway ปัจจุบัน
GET/pathway-templatesรายการ template ทั้งหมด
GET/pathway-templates/{code}ดู template ตาม code
GET/visitsรายการ Visit ทั้งหมด
GET/visits/{id}ดู Visit + steps
PATCH/visits/{id}/steps/{stepOrder}อัปเดตสถานะ VisitStep

⭐จุดเด่นของการออกแบบ

ทำไม flow นี้ถึง scale ได้และดูแลง่าย

⚡
Auto-create Visit+Steps
แค่เลือก template ระบบสร้าง Visit และ steps ครบใน transaction เดียว — ลด human error
🧩
Stages เป็น JSONB
ปรับจำนวน/ลำดับขั้นตอนได้ต่อ template โดยไม่ต้อง alter table
🏷️
Special Conditions
เก็บ flag เฉพาะผู้ป่วย (งดน้ำงดอาหาร, ใช้รถเข็น) เพื่อปรับ flow UI
🔢
stepOrder = 1, 2, 3…
URL ใช้ stepOrder แทน internal id — อ่านง่าย, debug ง่าย
🔒
Unique (visit_id, step_order)
ป้องกันการสร้างขั้นตอนซ้ำซ้อนใน Visit เดียวกัน
♻️
Idempotent Seed
pathway.Seed() รันซ้ำได้ — ไม่ duplicate template ตอน restart
